# 파이프라인 설계 선택 기록

2026-11-02, HYUNGU 기준. 구현의 선택 이유와 비교 후보를 남긴다.
**DOE 실행계획·실험 결과가 아니며 evaluation 코드는 변경하지 않는다.**
기준 커밋은 실험 실행 때 기록한다. 표의 영향은 검증할 가설이지 성능 개선의 확정 사실이 아니다.

## 개발 요청서 1~7번의 선택

| 단계 | 현재 선택 | 비교 가능한 대안/후보 | 선택 이유 | 비교할 지표·주의 |
|---|---|---|---|---|
| 1. 목표 | 기술 경험·결정을 근거 기반 카드로 생성. 수집기·이슈 변환·사후 개선 제외 | 범위 확장은 별도 과제 | MVP의 책임 경계 유지 | 범위 자체는 현재 실험의 고정 조건 |
| 2. 사전 확인 | 현재 로컬 코드·팀 규칙·API/DB 계약 우선, 가짜 의존성 테스트와 실제 호출 검증 분리 | 다른 브랜치를 기준으로 비교하려면 기준 구현을 먼저 명시 | 서로 다른 모델/그래프의 결과 혼합 방지 | HEAD, 미커밋 diff, 설정, 프롬프트 해시를 모두 기록 |
| 3. 추출 스키마 | 필드별 value/status/evidence_refs + evidence_index, 0~N 경험, 선택적 위치 | 같은 근거를 필드마다 내장하는 구조 등. 고정 계약 변경이 필요한 후보 | 사실 상태·근거를 Draft/Verify까지 추적 | 필드 정확도, 상태 승격, 근거 일치. 근거 없는 값 생성은 대안으로 허용하지 않음 |
| 4. Parse/Normalize/Chunk | 형식별 파서→DocumentIR, 구조 경계·표/코드/로그 보존, 기본 목표 6000자 | 3000/9000자, 인접 문맥/중첩 추가, 다른 파서 | 원문 위치와 의미 단위를 보존하면서 입력 크기 제한 | 사례 재현율·중복·원문 손실·토큰. target_chars는 Graph 입력으로 선택 가능, 나머지는 미구현 후보 |
| 5. Extract/Draft | 청크별 추출과 경험별 작성 분리, 확정 사실만 본문 복사, 파생 교훈은 inferred 유지 | 관련 청크를 묶어 추출, 동일 사건을 먼저 집계, 가설 전용 표현 정책 | 출처/사실 상태 손실과 임의 보완 방지 | 누락·중복·인과 오인·환각. 대안은 현재 구현되지 않음 |
| 6. MVP Gate | 규칙 선행 + LLM 의미 검증 기본 on, 원인별 제한된 재작성 | 명시적 규칙 전용 모드, 검증 모델 변경, 주장을 나누는 방식/보류 기준 변경 | 근거 불일치·가설 승격 검증. 오류를 자동 pass로 바꾸지 않음 | 나쁜 초안 검출·좋은 초안 오차단·주장 지지·비용. false 모드는 의미 미확인을 보류하며 검증 완화와 다름 |
| 7. 임베딩 | pass 카드의 content/situation/solution/lesson 최대 4관점, 결정적 템플릿·최소 조건, KURE 1024차원 | 검색 실험에서 관점 선택·템플릿·모델/차원 비교 | 검색 목적별 표현과 기존 vector(1024) 저장 계약 유지 | 검색 재현율·순위·지연·비용. **현재 카드 생성 평가에서 임베딩은 생략되므로 환각 점수에 직접 영향을 주는 요인이 아님** |

## 이번 리뷰 1~7번의 보완 선택

| 리뷰 항목 | 선택한 방식 | 다른 선택지 | 판단 이유/현재 한계 |
|---|---|---|---|
| 1. 단계 계산 | 초기화 때 실제 Gate 예산 스냅샷. 확정된 Draft=경험, Extract=근거 청크, Parse/Normalize/Chunk=해당 문서 전체. 미정 재처리는 가장 큰 문서 전체까지 예약 | 일괄 최대 5회×전체 청크 / 근거 청크만 항상 가정 / 문서별 별도 그래프 | 첫 방식은 과도한 거부, 두 번째는 상위 재처리 과소 추정. 기본 한도는 20000으로 늘려 정상 업로드 여유 확보 |
| 2. 실패 격리 | 문서별 JOB_TOO_LARGE와 합계 예산 JOB_STEP_BUDGET_EXCEEDED 분리. 부족하면 작은 문서 우선, 동률은 입력 순서 | 전체 작업 중단 / 입력 순서 우선 / 자동 분할 작업 | 큰 문서 하나가 다른 문서를 막지 않게 함. 자동 작업 분할·재접수는 미구현. 제외율/완료율을 카드 품질과 별도 집계 |
| 3. 보존 | 로컬 SQLite, job ID별 최신/이력 보존. 전체 완료+최종 결과 DB 기록 뒤 해제 | 메모리만 / 중앙 Postgres 체크포인터 / 제한된 TTL | 프로세스 종료 후 검토 자료 유지. 단일 호스트 영속 볼륨 필요. 제품 자동 재개·승인·TTL은 미구현 |
| 4. 동시 쓰기 | WAL 사용, busy_timeout 30초, 초기화의 BUSY/LOCKED만 최대 5회 재시도, 2개 Job 동시 테스트 | 전체 직렬 실행 / 서버 큐 / 중앙 DB | 실제 초기화 충돌을 재현해 보완. 테스트 통과가 대규모/다중 호스트 처리량 보장은 아님 |
| 5. 부분 저장 | pass만 저장, needs_review + saved_card_ids, 보류 근거 정리 금지 | 문서 전체 보류 / 보류 카드 별도 테이블 | 유효 카드의 저장을 막지 않음. 현 RPC는 같은 문서의 변경된 해시를 거부하므로 추가 승인 저장은 C05 후속 |
| 6. 대기 기록 | 성공·최종 실패에서 retry_delay_seconds를 0으로 초기화 | 이전 대기 유지 | pending 상태와 완료 이력의 혼동 방지. 품질 실험 요인은 아님 |
| 7. 의존성 | 직접 import하는 langchain-core를 직접 의존성에 선언 | langgraph의 간접 의존성에만 의존 | 설치 계약을 명확히 함. 품질 실험 요인은 아님 |

## 나중에 DOE로 전개할 때

### 2026-11-02 정보 부재·승인 상태 진단 후 추가 선택

| 요인 | 이번 선택 | 비교 후보/유지 조건 |
|---|---|---|
| 정보 부재 | 입력에서 못 찾았다는 관찰을 cause/outcome의 confirmed 사실로 만들지 않는다. 원문 명시 부정은 허용 | 정규식으로 모든 부정 표현을 차단하지 않는다. LLM 의미 판정과 범위 메타데이터를 사용 |
| 설계 승인 | Accepted만으로 실행·검증 결과를 대신하지 않는다. 선택·이유는 보존 | outcome 없는 ADR도 확인된 접근+선택 이유 또는 근거 있는 교훈으로 생성 가능 |
| Gate 문맥 | 지지 근거와 별도로 같은 문서의 온전한 블록을 최대 12000자 제공. 전체 입력 48000자 상한도 유지 | context_max_chars=0은 인용만 보는 비교 조건. 인접 블록 우선 선택이며 최적화된 수치는 아님 |
| 근거 경계 | 추가 문맥을 지지 근거로 승격하지 않는다. 반박 ID는 counter_evidence_refs에 별도 기록 | 배정되지 않은 지지 근거·존재하지 않는 반박 ID는 거부 |
| 문서 범위 주장 | 모델이 requires_document_scope로 식별한 supported 주장은 전체 원문 범위가 아니면 보류 | 식별 자체의 모델 오류는 남는다. 문맥 제공이 사실성 보장을 의미하지 않음 |
| 재처리 | 문맥 확장 전략이 없는 context_missing은 needs_review로 남긴다 | 같은 청킹·유료 호출 반복을 피함. 실제 문맥 확장 재시도는 후속 후보 |
| 진단 | supported를 포함한 의미 판정·이유·범위·입력 해시를 verification_traces에 보존 | 모델의 내부 사고를 추정하지 않고 반환한 사유만 기록. 사전 규칙 실패는 기존 issues 사용 |
| 청킹 | 이번 수정에서는 섹션 분리 정책을 유지 | 소문서 통합/인접 문맥 청킹은 별도 요인으로 비교. 이번 결과로 청킹 원인을 확정하지 않음 |
| 조정 자료 | Token Glance ADR 0001과 release v0.1.1을 조정용으로 사용 | 출력 비노출 독립 평가에는 다른 문서를 사용. 교훈 단위 정답표는 별도 작성 |

실제 모델 실행의 입력·출력·비용용 토큰 기록은 Git 제외 `.local/`에 둔다.
평가 브랜치의 판정 규칙·프롬프트를 이번 생성 결과에 맞춰 수정하지 않는다.

저장 연결 추가 선택(2026-11-02): main의 비원자적 create_card 반복 호출 대신 문서 원자 RPC를
유지하고 일반 dict 어댑터로 타입 결합만 제거했다. 단건 저장 서비스로 통합하는 대안은 같은
원자성·멱등성·0건 영수증을 확보해야 한다. 이 선택은 생성 환각보다 저장 완결성/중복/복구 지표에 영향을 준다.

- 우선 변경 가능한 요인만 구분한다: 청크 크기, 단계별 모델 구성, 의미 검증 on/off, 재작성/호출 예산 등.
  근거 추적 제거·미확인 원인 창작·실패를 pass로 처리하는 것은 비교 대안이 아니라 고정 금지 조건이다.
- 모델/청킹/프롬프트는 생성 품질 요인이다. 저장·단계 한도·재시도·체크포인터는 주로 완료율/비용의 요인이다.
  임베딩 요인은 별도 검색 평가로 분리한다. 실패/제외 때문에 카드가 없는 것을 환각으로 집계하지 않는다.
- 첫 비교에서는 한 요인씩 바꾸거나 소수 요인의 조합을 정하고 나머지 설정·원문·분할표·정답표를 고정한다.
  같은 Extract/Draft를 고정한 Gate 비교와 전체 생성 파이프라인 비교는 분리한다.
- 같은 평가 문서로 프롬프트를 조정하고 그 점수를 그대로 확정하지 않는다. 조정용/평가용 분리를 유지한다.
  모델 비결정성 때문에 필요하면 반복 실행을 설계하고, 회차·시도·모델 버전·예산·토큰·실패 사유를 남긴다.
- 후보 대안이 아직 구현되지 않았으면 설정 하나로 전환 가능한 것으로 표기하지 않는다.
  첫 초안/재작성 계보와 Gate 지표 분모가 정확한지도 평가 쪽에서 확인한 후 실험한다.
