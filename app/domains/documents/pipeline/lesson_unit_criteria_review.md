# 교훈 단위 기준의 작성 경위와 적용 경계

## 현재 기준 버전 — v0.3 평가 방법 보완

현재 적용할 문서 묶음은 [기준 v0.3](lesson_unit_criteria_v0.3.md)과
[평가 방법론 v0.1](lesson_evaluation_protocol_v0.1.md)이다.
v0.2 본문과 해시를 보존하기 위해 추가 내용은 새 버전으로 기록했다.

- 정답표 밖 카드의 타당/부당/경계 판정, 1:1/1:N/N:1 대응, 분모와 경계 처리를 추가했다.
- 판정자 둘의 출력 비노출 독립 라벨링, 합의 전 원본 보존, 이견 정렬·해결·재시험을 추가했다.
- 방법론은 대화 이력을 상속하지 않는 별도 세션 `lesson_matching_method`에서 작성했다.
  [최초 전달문과 후속 논리 검토 지시](lesson_evaluation_method_brief.md)를 보관했다.
  원문·생성 카드·실험 보고서·수치는 전달하지 않았다. 후속 지시는 집계 상태의 상호 배타성,
  경계 처리, 주장 지지, 중복의 분모와 재시험 조건에 관한 것이었다.
- 방법론 본문은 그 세션의 최종 초안을 보관한 것이다. v0.3의 적용 요약과 이 작성 경위는
  출력을 아는 주 작업자가 통합했다. 따라서 v0.3 전체를 출력 비노출 산출물이라고 부르지 않는다.
- v0.3에는 기존 정답표와 연결된 카드에 새로운 교훈도 있는 경우 추가 후보를 찾도록
  적용 범위를 명시했다. 특정 생성 결과에 대한 판정이나 실측값을 반영한 규칙은 아니다.
- 가상 예시 4개는 절차 설명용이며 실제 데이터·정답표·판정자 일치도 측정이 아니다.
  실제 2~3개 문서 사전 시험은 미실행이다. 파이프라인·프롬프트·평가기 구현도 바꾸지 않았다.

각 문서의 해시와 변경 이유는 `lesson_unit_criteria_v0.3.manifest.json`에 기록한다.
방법론은 실제 시험 전 절차안이며, 시험으로 원칙 이견을 해결한 후 적용 버전을 고정한다.

## 입력 비노출의 한계에 대한 보충

v0.1 작성 세션은 실제 출력을 받지 않았지만, 전달 조건은 출력을 아는 주 작업자가 선택했다.
성공 관측 부재·사건별 강제 통합 금지·공통 근거 허용에 관한 조건에도 그 대화의 판단이
들어갔다. 입력 분리가 이 정책 선택까지 독립적으로 만들었다는 뜻은 아니다.
해당 세 조건은 출력 관찰 이후 사용자에 의해 확정 또는 재확정되어 v0.2에 기록됐다.
기존 교훈 단위 요구의 최초 결정 시점을 이후 청킹 실험의 결과로 바꾸어 기록하지 않는다.

## v0.2 — 2026-11-03 사용자 결정 반영

사용자 정책 결정은 [v0.2](lesson_unit_criteria_v0.2.md)에 기록했고 v0.3에도 유지했다.

- 독립 교훈당 1장과 같은 사건의 여러 교훈 허용을 재확정했다.
- 공통 근거 허용을 평가 기준으로 확정했다. 생성 장수를 늘리는 지시는 추가하지 않는다.
- 성공 관측 없는 자료의 근거 충분한 교훈은 정답표에 포함한다.
  공개 정책은 유형별 환각 측정 후 결정한다. 공개 승인이나 기존 공개 로직의 변경은 아니다.

v0.2는 결과가 노출된 대화의 사용자 결정에 따른 개정이다. 아래 v0.1 작성 경위의
출력 비노출 성격을 v0.2 전체에 적용하지 않는다. v0.1 본문·전달문·해시는 보존했다.
세부 판정/측정안까지 모두 확정된 것은 아니며 v0.2에서 확정 범위와 제안을 구분한다.

## 이번에 완료한 것

- [기준 v0.1](lesson_unit_criteria_v0.1.md)을 검토용 고정 초안으로 보관했다.
- 기존 결과를 본 주 작업자가 기준 본문을 작성하지 않았다. 대화 이력을 상속하지 않는
  별도 Codex 작업 세션(`fork_turns=none`, `lesson_unit_criteria`)에
  [전달문](lesson_unit_criteria_brief.md)의 요구사항만 전달했다.
- 작성 세션에는 원문·생성 카드·실험 보고서·문서명·측정값·코드·프롬프트를 전달하지 않았다.
  파일·도구·웹·저장소를 읽지 않도록 지시했고 반환된 기준 본문을 내용 변경 없이 보관했다.
- 기준과 전달문 SHA256은 `lesson_unit_criteria_v0.1.manifest.json`에 기록한다.
  생성 결과에 맞춰 v0.1을 덮어쓰지 않는다. 변경 시 새 버전과 변경 이유를 남긴다.

이는 **같은 Codex 환경에서 대화 입력을 분리한 작성**이다. 별도 기관/모델의 독립 검토,
사용자 승인, 기술적으로 파일 접근을 차단한 보안 격리, 평가 데이터 분할 또는 정답표 완성을
의미하지 않는다. 주 작업자는 기존 출력을 알고 있으며 본문 수령 뒤 적용 경계만 별도로 기록했다.

다른 새 세션에서 기준만 검토하려면 전달문과 기준 본문만 제공한다. 기존 대화·IDE의
생성 카드/보고서 탭·진단 폴더·저장소 전체를 함께 전달하면 같은 비노출 조건이라고 볼 수 없다.

## 실행 지침으로 옮기기 전에 확인할 것

| 구분 | v0.1의 의미 | 이번에 하지 않은 것 |
|---|---|---|
| 사용자 확정 | 독립 교훈당 1장, 공통 사건에서 여러 교훈 가능, 문서 근거와 사실 상태 유지 | 사건당 1장으로 변경하지 않음 |
| 작성자 제안 | 독립성 판정 절차, 중복 기준, 근거 충분성, 경계 사례 처리 | 사용자·팀 승인 사실로 기록하지 않음 |
| 가설 중심 후보 | 작성자는 근거가 충분하면 가설·미검증임을 유지하며 채택하는 기본안을 제안 | `hypothesis`를 `confirmed`로 바꾸거나 DB `active` 공개 정책을 확정하지 않음 |
| 채택/보류/생략 | 문서에서 교훈 후보가 성립하는지에 관한 정답표 작성 판단 | Gate의 pass/retry/needs_review 또는 DB 상태와 동일시하지 않음 |
| 상태 병기 | 사람/판정자의 주장별 기록에서 가설·추론과 불확실성 등을 함께 설명 | 현 `FactStatus`에 여러 값을 넣거나 스키마를 변경하지 않음 |
| 의미 포함과 카드 단위 | 한 카드가 여러 교훈을 담은 경우 내용 누락과 단위 위반을 별도로 기록 | 카드 장수만으로 재현율·중복률을 계산하지 않음 |

특히 가설 중심 후보의 정답표 포함/공개 기준은 새 제안이다. 이 기준안을 근거로
현 Draft의 최소 생성 요건을 자동 완화하지 않는다. 후속 단계에서 확정 요구·제안 정책·
현재 구현을 대조하고 적용 범위를 명시해야 한다.

## 후속 순서

1. 가설 중심 후보 등 제안 정책을 검토하고 평가에 사용할 기준 버전을 명시한다.
2. 출력 비노출 상태에서 기준을 적용한 문서별 정답표와 분할·통합 이견을 작성한다.
3. 확정된 기준에 맞춰 Extract/Draft의 단위를 정렬한다. 이번에는 프롬프트·코드를 바꾸지 않았다.
4. 실제 요청 크기 기반 통합 모드 대체 경로를 별도로 보완하고, 적용된 모드를 기록한다.
5. 설정·기준 버전을 고정한 뒤 반복 A/B를 수행한다. 과거 관측값을 새 기준으로 몰래 재채점하지 않는다.

압축·캐시·일괄 검증을 앞당기지 않는다. 평가 브랜치의 규칙·프롬프트와 데이터셋은 수정하지 않았다.
