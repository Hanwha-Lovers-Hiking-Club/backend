# 문서 파이프라인 개발 체크리스트

설계·입출력 계약과 임베딩 구성은 [planning.md](planning.md)를 참고한다.
완료 표시는 구현 또는 확인한 항목에만 한다. 가짜 함수 구현과 실제 저장/그래프 연결을 구분한다.

독립 가짜 함수 외 기능 코드는 주석 단계다. 실제로 확인한 항목만 완료 처리한다.

## pipeline에서 먼저 확인·구현할 항목

- [ ] 상위 service에서 받는 문서 참조와 graph의 반환 결과를 합의한다.
- [ ] `models.py`와 `state.py`의 필드·타입·필수 여부를 정하고 상대 담당자에게 공유한다.
- [ ] PDF/DOCX/XLSX/MD/TXT별 대표 자료로 추출 순서·표/코드·원문 위치 보존을 확인한다.
- [ ] 형식별 파싱 결과를 공통 처리에 필요한 형태로 연결하되 형식 고유 위치를 잃지 않는다.
- [ ] 읽기 실패·텍스트 없는 PDF·빈 콘텐츠·인코딩 문제의 구분과 처리 기준을 정한다.
- [ ] 청킹 기준을 정하고, 잘린 표/코드·중복 청크가 근거 추적에 미치는 영향을 확인한다.
- [ ] 문서 제목을 원래 파일명과 동일하게 유지한다. LLM의 제목 수정 결과를 채택하지 않는다.
- [ ] 추출·초안 프롬프트와 구조화 모델을 맞추고 근거 없는 내용을 채우지 않는다.
- [ ] DB 필수 필드 구조 검증과 LLM 내용 검증을 나누고 판정 이유를 추적한다.
- [ ] 통과/재작성/폐기 분기·재작성 종료 조건과 카드 상태 매핑을 합의한다.
- [ ] 카드 저장 함수의 입력·반환값·카드+근거 원자성·재시도 책임을 다른 담당자와 합의한다.
- [x] 독립 가짜 저장 함수를 구현한다. 실제 DB 생성 수 0과 fake 표시를 반환한다.
- [ ] 가짜 저장 함수로 연결을 확인하고 실제 저장 성공과 구분한다.
- [ ] 실제 함수 제공 후 연결을 바꾸고, 저장 실패가 완료/성공으로 보고되지 않는지 확인한다.
- [ ] 카드 0개·일부 문서 실패의 최종 결과 기준을 합의한다.
- [x] 네 가지 임베딩의 관점과 구성 필드를 사용자 설명 및 PDF로 확인한다.
- [ ] 네 관점의 입력 조립·빈 필드 처리·모델·저장 계약을 확정한 뒤 embed 노드를 구현한다.
- [ ] 외부 비용 없는 단위 테스트와 필요한 graph 연결 테스트, Ruff 검사를 수행한다.

## 임베딩 구현 전 결정 항목

- [ ] 빈 필드·불완전 카드의 벡터 생성 조건과 누락 관점 처리.
- [ ] 입력 텍스트의 라벨·필드 순서·길이 제한·템플릿 버전.
- [ ] 임베딩 모델·차원·배치 크기·실패/재시도 정책.
- [ ] 기존 스키마에 없는 네 벡터를 컬럼/별도 테이블 중 어디에 저장할지와 카드 ID 연결.
- [ ] 카드+근거+벡터 저장 실패의 원자성/복구 기준, active 공개 시점.
- [ ] 카드 수정 시 어느 관점을 재계산할지와 변경 감지 기준.
- [ ] 검색 관점 선택·복수 검색 결과 통합·리랭킹. 타 담당자와 연결 계약만 합의.

## 상위 문서 도메인 / 다른 담당자와 연결할 항목

- [ ] documents 담당: 다중 업로드 API, 형식/용량 검증과 Storage 원본·문서 메타 저장.
- [ ] documents 담당: 백그라운드 작업 실행과 진행 상황/SSE 연결 계약. API 경로·응답은 실제 명세와 대조.
- [ ] knowledge_cards 담당: 실제 저장 함수와 카드+근거 저장 결과·오류·원자성 계약.
- [ ] DB/Storage 담당: 실제 버킷 허용 형식·용량·권한과 스키마 적용 상태 확인.
- [ ] 챗봇 담당: 검색 대상 카드 상태와 저장 완료 시점에 관한 연결만 확인. 챗봇 본문은 별도 담당.
- [ ] 문서 제목 정책의 표현 차이를 공유 문서 담당자와 정리한다.

기존 PR 템플릿의 서버 확인·구조 준수·스키마 문서 동기화 체크도 유지한다.
기능 테스트는 실행 결과가 있을 때만 체크한다. 실제 외부 연동 검증과 가짜 테스트 결과를 구분해 보고한다.
