## 1. 확정 범위와 판정자 구성

기존 사용자 확정 3건을 유지한다. **독립 교훈당 1장**, 각 교훈을 실제로 지지하는
**공통 근거 재사용 허용**, **성공 관측이 없어도 근거가 충분하면 정답표에 포함**한다.
같은 사건·문단·조치 수를 카드 수로 대체하지 않으며, 정답표 포함을 공개 승인으로 해석하지 않는다.

| 단계 | 사용자 확정 구성 | 접근·역할 경계 |
|---|---|---|
| 정답표 G0 독립 작성 | A = Claude 새 세션, B = GPT 새 세션 | 저장소·코드·생성 출력·상대 판정에 접근하지 않고 같은 요청문·같은 입력 파일을 받음 |
| G0 이견 조정 | 사용자(사람) | 해당 문서의 생성 출력이 아직 없을 때만 수행. G0 확정 후 그 문서로 파이프라인 실행 |
| 카드 사후 판정 | Claude 새 세션이 전체 카드 판정 | 익명 카드·원문·확정 G0·카드 판정 기준 안내 사용. GPT는 카드 판정에 사용하지 않음 |
| 사람 표본 검수 | 사용자 또는 지정한 사람 | Claude 판정을 보지 않고 먼저 판정한 뒤 비교. 표본 수치는 7장의 확정 절차 |
| Codex 및 이 저장소의 작업 세션 | 문서·입력 묶음 준비만 | 정답표 작성자·판정자·이견 조정자가 될 수 없음 |

이 구성의 이유는 다음과 같다.

- 평가 대상 생성 모델은 Extract/Verify `gpt-6.1-sol`, Draft `gpt-6-luna`다. 같은 계열
  출력을 더 후하게 볼 수 있는 자기 선호를 줄이기 위해, 카드를 읽는 판정은 Claude와 사람이 맡는다.
- G0 작성자 둘이 같은 계열이면 공유 편향으로 일치도가 실제보다 높아질 수 있어 Claude + GPT로 구성한다.
- G0 작성은 생성 출력을 보지 않으므로 자기 선호 문제는 작다. 다만 파이프라인과 같은 모델이
  무엇을 교훈으로 볼지 비슷하게 선택하면 재현율이 부풀 수 있다. GPT 작성자는 단계 모델과 다른
  모델을 권장하고, 같은 모델을 쓰면 모델 ID와 함께 한계로 기록한다. 다른 모델도 같은 계열의
  편향을 완전히 제거하지는 못한다.
- Codex와 저장소 작업 세션은 코드·생성 출력에 노출됐다. 새 세션이라는 이름만으로 이 세션을
  평가 역할로 재사용하지 않는다. 조정자인 사용자는 파이프라인의 일반 동작을 알고 있다는 한계도 남긴다.

자기 선호와 공유 편향은 설계상 우려이며 이번 평가에서 크기를 측정한 결과가 아니다.
모델의 실제 ID·사용 경로는 아직 지정하지 않았으며 아래 기록으로 실행 시 확인한다.

모든 판정 결과와 조정·검수 결과에 **모델 ID(사람은 해당 없음 + 역할 식별), 사용 경로(API/웹,
사람은 수동), 요청문 버전, 날짜, 입력 파일별 SHA-256**을 연결한다. 기준 안내·원문·확정 G0·
익명 카드 등 그 단계에서 실제 받은 파일을 모두 포함한다. 요청문 A/B의 본문을 고치지 않고
운영자가 별도 판정 정보 기록으로 연결한다. 세션 식별·독립 작성 여부·출력 비노출 여부·결과 파일
해시도 보존한다. 새 세션의 외부 파일·저장소 연결을 차단하며 접근 중 오염이 발견되면 중단·기록한다.

## 2. 독립 교훈의 정의와 분할·통합

독립 교훈은 문서 근거를 바탕으로 **어떤 조건에서 무엇을 판단하거나 실행해야 하는지**를
다른 교훈과 구별해 설명할 수 있는 하나의 배움이다. 다른 교훈과 독립적으로 수용·기각할 수
있어야 하며 적용 범위와 확실성은 근거 수준으로 제한한다.

1. 문서의 관측 내용, 명시된 해석·가설, 제안·조치를 구분한다.
2. 후보별 적용 조건과 핵심 판단·행동을 적고, 근거 없는 내용은 채우지 않는다.
3. 하나를 제거해도 다른 후보에 별도의 판단·행동이 남고 각각 근거가 있으면 분리한다.
4. 적용 조건과 핵심 판단·행동이 같고 표현·근거 위치만 다르면 통합한다.
5. 같은 원칙의 절차·조건·예외·뒷받침 사실은 함께 둔다. 별도로 적용할 배움이 있을 때만 분리한다.

같은 사건이라는 이유로 서로 다른 교훈을 합치지 않는다. 교훈 수를 늘리기 위해 하나의 교훈을
잘게 나누지 않는다. 교훈 수에 목표는 없으며 0개도 정상적인 결과다.

## 3. 공통 근거와 중복

같은 원문 문장·블록을 여러 교훈에 사용할 수 있지만 각 교훈을 실제로 지지하는지 따로 확인한다.
근거를 다시 쓸 수 있다는 것이 교훈을 추가할 이유는 아니다.

- 중복: 같은 적용 범위에서 실질적으로 같은 판단·행동이며, 합쳐도 독립적인 배움이 사라지지 않는다.
- 관련: 사건·근거·원인·목적을 공유하지만 서로 다른 판단·행동을 제공한다.

공통 근거로 최소 장수를 채우거나 카드 수를 늘리지 않는다. 공통 근거 자체가 환각을 늘린다는
결론을 내리지 않고, 개별 주장 지지와 의미상 중복을 확인한다. 이번에 생성 프롬프트는 수정하지 않는다.

## 4. 근거 충분성과 정답표 포함

출처 위치를 확인할 수 있고, 핵심 주장과 적용 범위를 원문으로 설명할 수 있어야 한다.
관측과 해석을 구분하고 추론의 연결 이유를 제시하며, 인과관계·효과·일반화의 강도가 근거 수준을
넘지 않아야 한다. 원문이 사실로 진술했다는 것은 문서 밖 세계에서 검증됐다는 뜻이 아니다.

성공 관측이 없다는 이유만으로 제외하지 않는다. 실패 기록, 설계 선택·이유, 위험 분석,
미해결 문제, 명시된 가설·제안에서도 충분한 근거가 있는 독립 교훈을 포함한다.
제안은 제안으로, 가설은 가설로 유지하며 예상 효과를 관측 결과로 바꾸지 않는다.
원문에 없는 사실·원인·결과·일반화가 있어야 성립하는 후보는 넣지 않는다.

- 경계 목록: 합리적인 해석이 갈리고 원문·기준만으로 결정할 수 없는 후보와 해소 조건.
- 생략·보류한 후보: 독립적인 배움 없음, 근거 부족, 원문에 없는 일반화 필요, 출처·문맥 충돌 등의 이유.

불확실성을 숨기지 않는다. 인식 상태는 주장별로 **사실 진술 / 가설 / 추론 / 미확인 / 충돌**을 기록한다.

## 5. 유형 표시와 공개 정책

정답표 채택은 문서가 교훈을 뒷받침한다는 평가 판단이다. Gate의 pass, DB의 active나 공개 승인이 아니다.
성공 관측 없는 자료의 공개 정책은 유형별 환각 측정 후 결정한다. 이번에 공개 로직·DB는 변경하지 않는다.

G0 확정 교훈과 사후 판정의 모든 카드에 다음을 기록한다. 카드 단계의 항목 이름은 **E 유형**이다.

| 필드 | 값과 주의 |
|---|---|
| 성공 관측 | 있음 / 없음 / 판단 불가. 원문 근거 위치를 남기고, 읽지 못한 내용을 없다고 단정하지 않음 |
| 자료 성격 | 실패 관측 / 설계 선택·이유 / 위험 분석 / 미해결 문제 / 가설·제안 / 기타. 복수 가능 |
| 부당 유형 | 근거 없는 주장 / 원문과 불일치 / 원인·효과 단정 / 가설·제안을 사실로 승격 / 원문보다 넓은 일반화 / 기타 |

성공 관측과 자료 성격을 독립적으로 표시한다. 성공 결과가 있는 설계 문서도 있을 수 있다.
각 유형의 부당률은 **부당/(타당+부당)**으로 계산하고, 타당·부당·경계·전체 카드 수와
경계 포함 부당률 범위를 함께 보고한다. 자료 성격 복수 표기 카드는 해당 유형마다 한 번씩
포함하므로 유형별 분모를 서로 합쳐 전체 분모로 쓰지 않는다. 성공 관측 판단 불가는 별도 층으로 둔다.
사람 검수 결과는 Claude 전체 판정 집계와 구분하고 표본 층별로 보고한다. 자세한 분모는 방법론 6장을 따른다.

## 6. G0 기록 형식과 고정

두 작성자는 첨부 A `judge_request_g0_v1.md`의 같은 형식을 사용한다.

| 구획 | 필수 기록 |
|---|---|
| 판정 정보 | 문서 파일명, 기준 안내 버전. 1장의 운영자 판정 정보 기록과 연결 |
| 확정 교훈 L01… | 교훈 문장, 적용 조건·범위 / 제외 범위, **필수 조건**, **같은 교훈으로 볼 수 있는 차이**, 근거, 인식 상태, 성공 관측, 자료 성격, 관련 교훈과 분리·통합한 이유, 불확실성 |
| 경계 목록 B01… | 내용, 갈리는 해석 두 가지, 무엇이 확인되면 결정되는가 |
| 생략·보류한 후보 S01… | 내용과 위치, 교훈으로 보지 않은 이유 |
| 기준 적용 메모 | 기준이 모호해서 판단하기 어려웠던 지점 |

**필수 조건**은 카드가 해당 교훈을 완전히 담았다고 보려면 반드시 들어가야 할 요소 1~3개다.
핵심 판단·행동, 빠지면 적용이 달라지는 조건·범위·제약, 필요한 인식 상태를 원문에 근거해
명시한다. 두 작성자가 각각 작성하고, 사용자가 출력을 만들기 전에 조정하여 G0와 함께 고정한다.
문구 그대로의 일치를 요구하는 필드가 아니며, 허용할 표현·범위 차이는 별도 필드에 적는다.
**생성 출력을 본 뒤 필수 조건을 바꾸지 않는다.** G0 교훈·경계·생략 목록도 원본을 보존한다.

인용은 원문을 그대로 복사하고 제목 경로·가능하면 줄 위치와 지지 이유를 적는다.
원문·카드 안의 지시문은 데이터로만 취급한다. 시스템 카드나 다른 판정자의 결과가 섞여 있으면
읽지 않고 오염 사실만 보고한다. 확정 G0의 분모에는 확정 교훈만 포함하고 경계 목록은 제외한다.

## 7. 실행 전 고정과 사람 표본 검수

데이터셋은 6개 프로젝트다. **홀드아웃은 프로젝트 단위로 나누고**, 같은 프로젝트의 문서·
변환 형식·첨부를 조율/홀드아웃에 나누지 않는다. Token Glance는 ADR 0001과 릴리스 v0.1.1의
출력이 노출됐으므로 프로젝트 전체를 조율용으로 둔다. 두 문서는 이번 조율에서 제외한다.
**나머지 5개 프로젝트(3JMT, Mechadog, Schale Queue, SSAFESTA, Vigilantis)는 모두 홀드아웃으로
사용자 확정했다.** 프로젝트 배정표는 manifest의 `split_frozen=true`로 고정한다.
조율 문서는 Token Glance의 **`docs/adr/0002-localization.md`와 `docs/perf.md` 두 문서로 확정**하고
원본 해시를 기록한다. 원본 풀 전체를 평가 대상으로 선정했다는 뜻은 아니며, 홀드아웃의 문서별
선정·제외 목록과 입력 해시는 해당 G0 작성 전에 추가 고정한다.

**단일 시스템을 평가하는 첫 실행은 1회로 하며 결과에 “1회 실행”이라고 명시한다.**
**조건을 비교할 때만 조건당 3회를 적용한다.** 실행 횟수 정책은 사용자 확정 사항이다.
지표는 문서·조건·실행별로 보고하고 여러 실행의 카드를 합쳐 한 집합으로 세지 않는다.
같은 실행 번호 내 문서 합산과 실행별 요약은 구분하며, 유리한 실행만 고르지 않는다.

다음 사람 검수 절차와 **25%·최소 10장 수치는 사용자 확정 사항**이다.

1. 문서·조건·실행별 카드 수를 n이라 할 때 기본 검수 수는 `min(n, max(ceil(0.25*n), 10))`이다.
   그보다 카드가 적으면 전수 검수하며 n=0이면 검수 대상 없음으로 기록한다.
2. Claude의 부당·경계 카드를 모두 포함한다. 이 수가 기본 검수 수보다 크면 모두 검수하므로
   최종 검수 수는 기본 수를 초과한다. 남은 수만큼 타당 카드에서 균등 무작위 추출한다.
3. 운영자는 추출 목록·난수 시드·모집단/층별 수를 보존하되 사람에게 Claude 라벨·이유·표본 층을
   주지 않는다. 사람은 같은 원문·G0·기준·익명 카드로 먼저 판정하고 결과를 저장한 뒤 비교한다.
4. **내용 타당성(A)** 불일치와 **G0 대응(C, 필수 조건·분절 포함)** 불일치를 나눠 보고한다.
   Claude 기준 **부당·경계 / 타당** 표본 층별로 모집단 수·검수 수·불일치 수·비율·사유를 따로 집계한다.
   층별 추출률이 다르므로 검수 표본 전체의 단순 부당률·일치율을 모집단 수치처럼 제시하지 않는다.
5. 같은 종류의 불일치가 반복되면 기준 보완 또는 검수 범위 확대를 검토하고 변경·재판정 범위를 기록한다.
   G0 필수 조건을 출력에 맞춰 고치지 않는다. kappa나 임의의 합격선을 강제하지 않는다.

## 8. 카드 사후 판정과 익명화

Claude 새 세션이 첨부 B `judge_request_cards_v1.md`로 전체 카드를 판정한다.
이 단계는 생성 출력을 읽는 사후 판정이며 출력 비노출 G0 작성과 구분한다.

| 축 | 요청문과 같은 출력 |
|---|---|
| A 내용 타당성 | 타당 / 부당 / 경계, 이유. 부당이면 문제 문장 인용과 유형, 근거 발췌 일치/불일치 |
| B 교훈 구성 | 교훈 없음 / 독립 교훈 1개 / 독립 교훈 여러 개(개수·각 내용) / 경계 |
| C G0 대응 | 관련 교훈마다 완전 / 부분 / 경계, 필수 조건별 충족 여부. 대응이 없으면 없음. 분절 완전은 함께 쓴 카드 ID 모두 기록 |
| D G0 밖 교훈 | 없음 또는 G+ 후보. 원문 위치·인용, 독립성·충분성·타당/부당/경계, 겹치는 G0 경계 ID |
| E 유형 | 성공 관측, 자료 성격(복수 가능) |

교훈별 대응 목록(대응 없음 포함), 같은 교훈을 반복한 카드 묶음, 정답표·기준 메모도 남긴다.
G0에 없다는 이유만으로 부당으로 판정하지 않는다. 이미 G0에 대응하는 카드 안의 다른 독립
교훈도 G+ 후보로 검토한다. G0를 고치지 않고 공통 확장표 결과는 별도로 보존한다.

익명화 내보내기는 G0 확정 뒤 별도 요청으로 수행한다. 이번에는 정의만 하며 내보내지 않는다.

- 남김: **무작위 카드 ID(C-…); 카드 본문 필드** `title`, `summary`, `context`, `problem`,
  `cause`, `approach`, `rationale`, `outcome`, `lesson`, `technologies`, `keywords`;
  **근거 위치·발췌** `location`, `excerpt`. 원문의 기술·프로젝트 맥락은 충실성 판단에 필요한 원문 내용이다.
- 제거: **시스템·실행·설정 이름**, 생성 모델/버전, 원래 카드/작업 ID, 파일명·정렬에 드러나는 출처,
  **Gate 판정**, 상태, **검증 사유(verification trace)**, **점수** 등 생성·내부 평가 메타데이터.
- 운영자만 보관: 무작위 ID와 원래 실행의 대응표, 섞은 순서·시드, 집계용 조건·실행 정보.
  판정자에게 전달하지 않는다. 본문을 내부 판정으로 보완하거나 내용을 의역하지 않는다.

## 9. 카드와 교훈의 대응·집계

완전은 핵심 주장·**G0 필수 조건**·인식 상태가 원문으로 지지될 때만 인정한다.
원문보다 넓은 무조건적 일반화는 완전이 아니다. 카드 전체가 부당이어도 별개 오류가 해당 교훈을
훼손하지 않으면 그 교훈의 대응은 완전일 수 있다. A와 C를 별도로 판정한다.

| 대응 | 내용 포착 | 별도 기록 |
|---|---|---|
| 1:1 | 필수 조건 등을 충족하면 완전 | 부분·범위 차이·경계 |
| 1:N | 지지되는 교훈 각각 포착 인정 | 카드에 여러 독립 교훈을 합친 단위 위반 |
| N:1 반복 | 고유 교훈 재현율은 한 번만 인정 | 초과 반복 대응·중복 묶음 |
| N:1 상호 보완 | 원문에 없는 연결 없이 합쳐 필수 조건 충족 시 분절 완전 | 단일 카드 완전과 구별 |

교훈별 상태는 완전 / 부분만 / 확정 누락 / 미해결 경계 중 하나다. 경계만 남은 교훈을 누락으로
확정하지 않고, 부분에 임의의 0.5점을 주지 않는다. 분모 0은 N/A다.
카드 타당률은 타당/(타당+부당)과 전체 카드 기준 경계 포함 범위를 병기한다.
서로 다른 단위의 수치를 임의의 F1·종합 점수로 합치지 않는다.
평가 카드 집합의 단계(초안·최종 등)를 실행 전에 지정하고 서로 섞지 않으며 Gate 판정을 정답으로 쓰지 않는다.

## 10. 사전 조율·독립성·버전 관리

확정한 조율 문서 2개에서 A/B가 독립 작성하고, 합의 전 원본을 보존한다.
1:1 / 분할·통합 / 대응 없음 / 경계를 의미·근거로 정렬하며 단순 교훈 수 일치를 판정 일치로 보지 않는다.
해당 문서에 생성 출력이 아직 없을 때 사용자가 이견을 조정한다. 이미 출력이 존재하거나 비노출
조건을 확인할 수 없는 문서는 이 절차의 G0 작성·조정 대상으로 진행하지 않는다.
반복되는 원칙 이견은 기준 보완·독립 재시험 대상으로 하고 개별 원문 모호성은 경계로 남길 수 있다.

조율 후 기준·요청문·분할표·반복 횟수·검수 수치·카드 집합 단계를 고정하고,
**문서별 A/B 독립 G0 → 사용자 조정 → G0 및 필수 조건 해시 고정 → 해당 문서 파이프라인 실행 →
익명화 → Claude 전체 판정 → 사람 표본 독립 검수** 순서로 진행한다.

기준·G0·G+·판정 결과·입력 파일의 버전과 해시, 한계를 보존한다. 출력 열람 뒤 발견한 G0 문제는
메모로 남기고 G0/필수 조건 원본을 덮어쓰지 않는다. 핵심 기준을 사후 바꾼 기존 문서 결과는
개발 결과로 구분하고, 확증 비교에는 새 프로젝트 홀드아웃을 사용한다.

판정자에게는 G0 작성에 필요한 내용만 담은 독립 안내와 요청문·원문을 준다.
검토 기록, `.local` 자료, 출력 관찰 manifest, 실제 생성 출력 사례를 주지 않는다.
이 문서 전체가 출력 비노출로 작성됐거나 독립 검증됐다고 주장하지 않는다.
