# Lessons Learned 카드 평가 방법론 v0.2

2026-11-04 (Asia/Seoul). [교훈 단위 기준 v0.4](lesson_unit_criteria_v0.4.md)와 함께 사용한다.

이 평가는 실제 세계의 진실 여부가 아니라 **원문에 충실한 교훈을 추출했는지**를 평가한다.
인식 상태(사실 진술 / 가설 / 추론 / 미확인 / 충돌)를 보존하며 내용 타당성과 독립 교훈당 카드
1장 규칙 준수를 별도로 측정한다. [v0.1](lesson_evaluation_protocol_v0.1.md)은 보존한다.
현재는 준비 단계이며 실제 이중 판정·G0 작성·이견 조정·평가 실행을 하지 않았다.
2026-11-04 사용자 후속 확정으로 표본 수치·실행 횟수 정책·프로젝트 분할표·조율 문서 선정을 고정했다.

## 0. 판정자·역할·판정 정보

| 단계 | 담당 | 독립성 조건 |
|---|---|---|
| G0 작성 A | Claude 새 세션 | 원문·G0 기준 안내·요청문 A만 받음. 저장소·코드·출력·B 결과 접근 금지 |
| G0 작성 B | GPT 새 세션 | A와 같은 파일·같은 요청문. A 결과 접근 금지. 단계 모델과 다른 모델 권장 |
| G0 이견 조정 | 사용자(사람) | 해당 문서의 생성 출력이 아직 없을 때만 조정 |
| 카드 전체 사후 판정 | Claude 새 세션 | 원문·확정 G0·카드 판정 기준 안내·요청문 B·익명 카드 사용 |
| 카드 표본 독립 검수 | 사람 | Claude 판정·이유·추출 층을 가리고 먼저 판정·저장 후 비교 |

평가 대상 생성 모델은 Extract/Verify `gpt-6.1-sol`, Draft `gpt-6-luna`다. 같은 계열 출력에
대한 자기 선호 우려 때문에 카드 판정은 다른 계열 Claude와 사람이 맡고 GPT는 쓰지 않는다.
G0는 출력을 읽지 않아 자기 선호 영향이 작지만, 같은 계열 작성자끼리는 공유 편향으로 일치도가
높아 보일 수 있어 Claude + GPT로 구성한다. GPT가 파이프라인과 같은 모델이면 교훈 선택이
비슷해져 재현율이 부풀 수 있으므로 다른 모델을 권장하고, 같으면 한계를 기록한다.
이 우려의 효과 크기를 측정한 것은 아니며 계열이 다르다는 것만으로 독립성이 보장되지는 않는다.

Codex와 이 저장소 작업 세션은 코드·생성 출력에 노출되어 **정답표 작성자·판정자·이견 조정자로
참여하지 않는다**. 문서와 입력 파일 준비만 한다. 사용자 조정자도 일반 파이프라인 동작을
알고 있다는 한계가 있다. 사용자에게 해당 문서의 출력이 생기기 전에만 조정을 맡기며,
이미 출력이 있거나 그 여부를 확인할 수 없으면 그 문서는 이 절차로 진행하지 않는다.

모든 판정·조정·검수 결과를 별도 운영자 판정 정보 기록에 연결한다.

- 모델 ID(별칭만 확인되면 제공된 이름과 정확한 ID 확인 불가를 함께 기록; 사람은 해당 없음과 역할 식별).
- 사용 경로: API / 웹, 사람은 수동. API/웹 세션과 평가 역할을 구분한다.
- 요청문 파일명·버전·SHA-256, 기준 안내 버전·SHA-256, 날짜(시간대 포함).
- 실제 전달한 **모든 입력 파일별 SHA-256**: 원문, 안내, 요청문 및 해당 단계의 G0·익명 카드 등.
- 결과 파일명·SHA-256, 독립 작성/출력 비노출 확인, 세션 식별, 오염·접근 한계.

첨부 요청문은 수정하지 않는다. 요청문 출력의 판정 정보에 없는 항목은 운영자 기록으로 결과마다
연결한다. 웹에서 정확한 모델 ID를 확인할 수 없으면 추정해 채우지 않는다. 작성자 A/B가 실제로
같은 입력 해시를 받았는지 대조하고 외부 저장소 연결·이전 대화를 제공하지 않는다.

## 1. 평가 단위와 G0 고정

독립 교훈은 다른 교훈과 독립적으로 수용·기각할 수 있는 하나의 판단 또는 행동 원칙이다.
같은 사건에서 판단·행동이 다르고 각각 근거가 있으면 분리한다. 같은 교훈의 설명·예시·조건
보충·절차 단계·표현 차이는 통합한다. 공통 근거는 각 교훈을 실제로 지지할 때 재사용한다.
성공 관측이 없어도 근거가 충분하면 포함하되 효과가 관측된 것처럼 서술하지 않는다.

문서별 G0는 요청문 A `judge_request_g0_v1.md`의 형식으로 작성한다.

| 구획 | 기록 항목 |
|---|---|
| 판정 정보 | 문서 파일명, 기준 안내 버전. 0장의 운영자 기록과 연결 |
| 확정 교훈 L01… | 교훈 문장; 적용 조건·범위 / 제외 범위; **필수 조건**; **같은 교훈으로 볼 수 있는 차이**; 근거(위치·원문 인용·지지 이유); 인식 상태; 성공 관측(+근거 위치); 자료 성격(복수 가능); 관련 교훈과 분리·통합한 이유; 불확실성 |
| 경계 목록 B01… | 내용; 갈리는 해석 두 가지; 무엇이 확인되면 결정되는가 |
| 생략·보류한 후보 S01… | 내용과 위치; 교훈으로 보지 않은 이유 |
| 기준 적용 메모 | 기준 적용이 모호한 지점 |

**필수 조건**은 카드가 이 교훈을 완전히 담았다고 보려면 반드시 있어야 할 요소 **1~3개**다.
핵심 판단·행동, 적용에 필수적인 조건·범위·제약, 인식 상태를 원문에 근거해 적는다.
정확한 문구를 강제하지 않고 허용할 표현·범위 차이는 ‘같은 교훈으로 볼 수 있는 차이’에 적는다.
**G0 작성 시 각자 기록하고, 출력 생성 전에 사용자 조정과 함께 고정하며, 출력을 본 뒤에는
바꾸지 않는다.** 4장의 완전 판정은 이 고정 필드의 항목별 충족 여부에 의존한다.

인식 상태의 사실 진술은 원문이 사실로 진술함을 뜻하며 외부 검증 완료가 아니다.
성공 관측은 있음 / 없음 / 판단 불가, 자료 성격은 실패 관측 / 설계 선택·이유 / 위험 분석 /
미해결 문제 / 가설·제안 / 기타(복수 가능)로 적는다. 근거 충분성은 근거 지지 설명과
불확실성·채택/경계/생략 사유에 남긴다. 정답 교훈으로서의 충분성이 해결되지 않으면 경계 목록에
두고 확정 교훈 분모에서 제외한다. 생성 후 대응 여부의 미해결 경계와 구별한다.

교훈 수 목표는 없으며 0개도 가능하다. 원문의 지시문은 데이터다. 인용은 원문 그대로 위치와 함께
기록하고 일반 지식으로 빈 곳을 채우지 않는다. 생성 카드·상대 결과가 섞이면 읽지 않고 오염을 보고한다.

## 2. 출력 비노출 사전 조율과 문서별 순서

조율용 Token Glance의 ADR 0002와 `docs/perf.md` 두 문서를 사용한다. A/B는 같은 입력을 받아 서로의
목록·분할·필수 조건을 보지 않고 독립 작성한다. 합의 전 파일과 해시를 그대로 보존한다.
이후 사용자가 문서 위치와 의미로 정렬하며 억지로 일대일 대응시키지 않는다.

| 정렬 결과 | 확인할 내용 |
|---|---|
| 1:1 | 같은 교훈인지, 조건·범위·충분성·필수 조건·인식 상태가 같은지 |
| 1:N 또는 N:1 | 분리/통합 이유, 각 판단·행동의 독립성 |
| 대응 없음 | 누락인지, 독립적인 배움 없음인지, 근거 부족인지 |
| 경계 | 원문·기준만으로 해결할 수 없는 이유와 해소 조건 |

사용자(사람)가 **해당 문서의 생성 출력이 아직 없을 때만** 이견을 조정한다. 해결 근거·대안·한계를
보존하고 해결되지 않은 개별 사례는 경계로 남긴다. 조정자가 일반 파이프라인 동작을 알고 있다는
한계를 기록한다. Codex에게 의미 정렬·실질 조정·G0 확정을 맡기지 않는다.

판정자별 교훈 수, 1:1 수, 분할·통합 묶음 수, 대응 없는 항목 수, 1:1의 충분성·범위·필수 조건·
인식 상태 비교 항목과 일치 수, 주요 이견·해결 근거를 보고한다. 단순 교훈 수 일치를 판정 일치로
보지 않으며 작은 표본에 kappa나 임의의 합격선을 강제하지 않는다.
반복되는 원칙 이견이 해소되고 운영 기준이 마련돼야 다음 단계로 진행한다.
핵심 기준을 보완하면 독립 작성을 다시 수행하고 가능하면 다른 조율 문서를 쓴다.
조율 문서는 홀드아웃 평가에 재사용하지 않는다.

실제 문서별 실행 순서는 다음과 같다. 조율 단계에도 G0를 쓰는 문서에는 같은 순서를 적용한다.

1. 사용자 확정 프로젝트 분할표와 조율 문서·해시를 manifest로 고정한다(완료, 10장).
   홀드아웃 문서별 대상·제외 목록과 해시는 해당 G0 작성 전에 추가 고정한다.
2. G0 A/B 독립 작성 → 독립 원본 보존 → 사용자 조정 → G0·경계·생략 목록·필수 조건 해시 고정.
3. 그 문서의 파이프라인을 실행한다. 다른 문서의 G0 완료로 이 문서의 순서를 대신하지 않는다.
4. 별도 요청에 따라 카드 익명화 → Claude 전체 판정 → 사람 표본 독립 검수 → 집계.

이번에는 문서·manifest의 확정 상태만 갱신했으며 실제 판정이나 파이프라인은 실행하지 않는다.

## 3. 생성 카드 사후 판정·익명화·사람 검수

### 3.1 판정 축과 담당

Claude 새 세션이 전체 카드를 요청문 B `judge_request_cards_v1.md`로 판정한다.
GPT는 카드 판정에 쓰지 않는다. 원문·확정 G0·카드 판정 기준 안내·익명 카드를 읽는 단계이므로
출력 비노출 평가라고 부르지 않는다. 점수·비율 계산은 판정자가 아닌 집계 담당자가 한다.

| 출력 축 | 판정 |
|---|---|
| A 내용 타당성 | 타당 / 부당 / 경계. 원문 기준. 부당이면 문제 문장 인용·오류 유형 |
| 근거 발췌 확인 | 일치 / 불일치(대상 발췌). 원문에 실제 존재하는지 확인 |
| B 교훈 구성 | 교훈 없음 / 독립 교훈 1개 / 독립 교훈 여러 개(개수·각 내용) / 경계 |
| C G0 대응 | 관련 L ID마다 완전 / 부분 / 경계와 필수 조건별 충족 여부. 없으면 없음. 분절 완전은 모든 카드 ID |
| D G0 밖 교훈 | 없음 또는 G+ 후보(위치·인용·독립성·충분성·타당/부당/경계·겹치는 B ID) |
| E 유형 | 성공 관측 있음 / 없음 / 판단 불가; 자료 성격 실패 관측 / 설계 선택·이유 / 위험 분석 / 미해결 문제 / 가설·제안 / 기타(복수 가능) |

타당은 중요한 주장과 인식 상태가 모두 원문으로 지지됨, 부당은 중요한 주장에 근거가 없거나
원문과 충돌함, 경계는 합리적인 해석이 갈리고 해소되지 않음이다. 부당 유형은 근거 없는 주장 /
원문과 불일치 / 원인·효과 단정 / 가설·제안을 사실로 승격 / 원문보다 넓은 일반화 / 기타다.
근거 발췌 불일치 사실은 내용 판정과 함께 기록하되 내부 Gate를 정답으로 삼지 않는다.

여러 교훈을 정확하게 담은 카드도 내용은 타당할 수 있다. 같은 교훈의 반복도 내용 타당성과 별개다.
G0 밖이라는 이유만으로 부당이 아니며, 카드 전체가 부당이어도 별개 오류가 해당 교훈의 핵심 주장·
필수 조건·인식 상태를 훼손하지 않으면 그 교훈 대응은 완전일 수 있다.

카드별 판정 외에 G0 교훈별 대응 목록(대응 없음 포함), 같은 교훈을 반복한 카드 묶음(G0/G+ 모두),
정답표·기준 메모를 받는다. G0 오류 의심은 메모에만 남기고 고치지 않는다.

### 3.2 익명화 입력 정의

남기는 항목은 다음으로 제한한다.

- 무작위 카드 ID `C-…`.
- 카드 본문 필드 `title`, `summary`, `context`, `problem`, `cause`, `approach`, `rationale`,
  `outcome`, `lesson`, `technologies`, `keywords`.
- 근거 위치·발췌 `location`, `excerpt`(복수 가능). 발췌를 원문에 맞춰 몰래 수정하지 않는다.

제거 항목은 시스템·실행·설정 이름, 생성 모델·버전, 원래 카드/작업 ID, 출처를 드러내는 파일명·
정렬 정보, Gate 판정·상태, 검증 사유(verification trace), 점수 및 기타 내부 생성 메타데이터다.
본문에 필요한 원문 기술·프로젝트 맥락은 유지한다. 원래 ID 대응표와 조건·실행 정보는 운영자만
보관하고 판정 입력·출력에는 무작위 ID를 쓴다. 카드 순서를 섞고 시드는 운영자 기록에 남긴다.
원문·G0 대응을 확인하는 데 필요한 문서 식별자는 중립적으로 연결한다.
익명화는 출처 메타데이터를 가리는 절차이며 내용만으로 출처를 추정할 가능성까지 제거하지는 못한다.

익명화 내보내기·카드 판정 기준 안내 작성은 G0 확정 뒤 별도 요청으로 진행한다.
현재 `cards/`에는 원문 요청문 B만 있고 실제 카드·G0·판정 결과는 없다.

### 3.3 사람 표본 검수 — 사용자 확정

문서별 검수 원칙을 비교 조건·실행마다 독립적으로 적용한다. 카드 수 n에 대해
`m0 = min(n, max(ceil(0.25*n), 10))`을 기본 목표로 한다. 카드 수가 25%와 10장 중 큰 수보다
적으면 전수 검수가 되며 n=0은 대상 없음이다.

Claude가 부당·경계로 판정한 카드 수를 h라 하면 모두 포함하고,
타당 카드에서 `max(0, m0-h)`장을 균등 무작위로 뽑는다. 최종 검수 수는 `max(m0,h)`이므로
부당·경계가 많으면 25%·10장을 초과한다. 추출 모집단·카드 ID·난수 시드·층별 추출률을 보존한다.

사람에게 Claude 라벨·이유·추출 층을 보여 주지 않는다. 동일한 원문·G0·기준 안내·익명 카드를
주고 먼저 독립 판정·결과 파일 해시 고정 후 Claude 결과와 비교한다.
분절 완전은 표본 카드의 판정에 필요한 동반 카드도 함께 제공·검수하고, 추가된 수와 이유를 기록한다.
추가 검수 카드도 실제 검수 수와 층별 표에 포함한다.

불일치는 **A 내용 타당성**과 **C G0 대응**으로 나눠 보고한다. C는 같은 카드–교훈 관계에서
라벨·필수 조건·분절 인정이 다른지 비교하며 관계 누락도 기록한다. Claude 기준 **부당·경계 / 타당**
표본 층별로 모집단 수·기본 추출 수·추가 수·실제 검수 수·비교 항목 수·불일치 수·비율·사유를 남긴다.
A는 카드 수, C는 카드–교훈 관계 수가 기본 비교 분모이며 서로 합치지 않는다. B/D/E 차이도 메모한다.
전수 층과 무작위 층의 단순 합산 비율을 모집단의 일치도·부당률로 일반화하지 않는다.

같은 종류의 불일치가 반복되면 사용자에게 기준 보완 또는 검수 범위 확대를 제안하고 영향을
받는 판정을 다시 확인한다. 그 반복의 횟수나 kappa·합격선을 임의로 강제하지 않는다.
출력을 본 뒤 G0 필수 조건을 바꾸지 않고 8장의 변경 규칙을 따른다.

## 4. 카드–교훈 대응 규칙

요청문 B의 C 축에 맞춰 관련 교훈마다 **완전 / 부분 / 경계**를 기록한다.
관련 교훈이 없으면 ‘없음’, G0 교훈별 목록에 대응 카드가 없으면 ‘대응 없음’으로 적는다.
표현 유사성보다 핵심 판단·행동, 적용 조건·범위, 인식 상태를 비교한다.

**완전은 핵심 주장, G0의 필수 조건 각각, 인식 상태가 모두 원문으로 지지될 때만 인정한다.**
조건별 충족/누락/경계를 적고, ‘같은 교훈으로 볼 수 있는 차이’에 고정된 허용 범위를 적용한다.
필수 조건을 출력에 맞춰 사후 변경하지 않는다.

| 대응 | 처리 |
|---|---|
| 카드 1장 → 교훈 1개 | 핵심 주장·필수 조건·인식 상태 충족 시 완전 |
| 카드 1장 → 교훈 여러 개 | 각 교훈의 내용 포착은 각각 인정, 합침 위반은 별도 |
| 카드 여러 장 → 교훈 1개 | 완전 반복과 상호 보완 분절을 구분 |
| 부분 | 중요한 조건·행동 등이 빠졌지만 일부 교훈은 지지됨 |
| 경계 | 원문·기준으로 관계를 확정할 수 없음 |

특정 조건에서만 지지되는 내용을 무조건적 원칙으로 넓히면 완전이 아니다.
더 좁은 범위라도 독립적으로 충분히 지지되면 G+ 후보일 수 있다.
여러 카드가 **원문에 없는 연결·추가 추론 없이** 합쳐서 필수 조건을 충족할 때만 **분절 완전**으로
기록하고 함께 쓰인 ID를 모두 남긴다. 단일 카드 완전과 구분하며 재현율에는 교훈을 한 번만 센다.

## 5. 교훈별 최종 집계 상태

G0의 확정 교훈마다 하나의 상태만 부여한다.

| 상태 | 정의 |
|---|---|
| 완전 F | 적어도 한 카드 또는 인정된 분절 완전 묶음이 완전히 포착한다고 확정 |
| 부분만 P | 완전 없음, 확정된 부분 있음, 집계 상태를 바꿀 미해결 대응 없음 |
| 확정 누락 M | 완전·부분 없음, 집계 상태를 바꿀 미해결 대응 없음 |
| 미해결 경계 B | 완전이 확정되지 않았고 미해결 대응으로 최종 상태가 달라질 수 있음 |

이미 완전이 확정되면 다른 경계가 있어도 완전이다. 부분과 경계가 함께 있고 경계가 완전이 될
가능성이 남으면 미해결 경계로 두고 ‘확정 부분 있음’을 보존한다.
경계가 부분/누락 구분만 바꿀 수 있어도 미해결 경계이며, 경계만 남은 교훈을 확정 누락에 넣지 않는다.
**N = F + P + M + B**. 여기서 B는 집계 기호이며 G0 경계 목록의 B01… ID와 다르다.

## 6. 지표·분모·실행별 보고

| 지표 | 분자 | 분모 |
|---|---|---|
| 확정 포착 재현율 | 완전 고유 교훈 수 F | G0 확정 교훈 수 N |
| 단일 카드 완전 포착률 | 단독 완전 카드가 있는 고유 교훈 수 | N |
| 부분만 비율 / 확정 누락률 / 미해결 경계율 | 각각 P / M / B | N |
| 카드 타당률 | 타당 V | 타당 V + 부당 I |
| 카드 합침률 | 독립 교훈 2개 이상 카드 수 | 교훈 개수를 확정한 카드 수 |
| 분절 포착 비율 | 여러 카드 결합으로만 완전인 고유 교훈 수 | F |

완전 가능성이 남은 미해결 교훈 수를 B_F라 하면 최종 재현율 범위는
**F/N ≤ 최종 재현율 ≤ (F+B_F)/N**이다. B 전체를 자동으로 상한에 더하지 않는다.
B=0이면 F/N이 최종 확정값이다. 단일 카드 완전 포착률의 경계도 같은 방식으로 보고한다.

카드 경계 수를 U라 하면 타당률은 V/(V+I), 전체 카드 기준 범위는
**V/(V+I+U) ~ (V+U)/(V+I+U)**다. V/I/U와 전체 수를 병기한다.
교훈 개수 경계, 교훈 없음, 분절 인정 경계도 따로 보고하고 부분에 임의의 0.5점을 주지 않는다.
내용·교훈 단위 지표를 임의의 F1이나 종합 점수로 합치지 않는다.

### 유형별 부당률

카드 E 유형의 성공 관측별, 자료 성격별로 V_t/I_t/U_t와 전체 T_t를 기록한다.
**유형별 부당률 = I_t/(V_t+I_t)**, 경계 해소 범위는
**I_t/T_t ~ (I_t+U_t)/T_t**다. 분모 0은 N/A다.
성공 관측은 있음 / 없음 / 판단 불가를 따로 보고한다. 자료 성격은 복수 표기 카드가 각 해당
유형에 한 번씩 들어가므로 유형 분모 합을 전체 카드 수로 쓰지 않는다.
오류 유형별 카드 수도 중첩 가능성을 표시한다. 공개 정책은 이 측정 뒤 결정하며 임계값을 미리 만들지 않는다.
Claude 전체 카드 판정 집계와 사람 검수 집계는 구분한다. 사람 결과는 3.3의 두 층과 추출률을
보존하고, 선택 표본을 단순 합쳐 전체 유형별 부당률로 제시하지 않는다.

### 중복 집계

최초 완전 반복 대응률은 G0를 사용한다. 교훈 g에 단독 완전인 카드 수를 n_g라 하면
분자는 `sum(max(0,n_g-1))`, 분모는 `sum(n_g)`다. **카드–교훈 관계 단위**이며 카드 수 비율이 아니다.
한 카드의 여러 완전 대응은 각각 기록하고 합침은 따로 센다. 상호 보완 묶음·부분 반복·미해결
완전 후보는 이 확정 지표에 섞지 않는다.
G0 밖 교훈도 G+ 후보 목록에서 의미상 중복 묶음·카드 수·초과 수를 기록한다.
확장표로 계산하면 G0∪G+ 버전을 명시하고 최초 결과와 구분한다.

### 반복과 합산

실행 횟수 정책은 다음과 같이 사용자 확정했다.

- **단일 시스템을 평가하는 첫 실행: 1회. 결과 보고에 “1회 실행”이라고 명시한다.**
- **조건 비교: 조건당 3회. 3회 정책은 조건을 비교할 때만 적용한다.**

동일 대상 문서·입력·카드 집합 단계와 조건별 설정을 운영자 manifest에 기록하고 각 실행을 식별한다.
실패·중단·재시도도 기록하며 유리한 실행만 선택하지 않는다. 운영 실패를 카드 0장 성공으로 대체하지 않는다.

**문서·조건·실행별 지표를 따로 보고하며, 여러 실행의 카드를 한 집합으로 합쳐 세지 않는다.**
같은 실행 번호 내 문서별 분자·분모 합산은 별도 전체 결과로 제시할 수 있다.
문서 평균이나 실행별 평균·범위는 보조 요약으로 구분하고 실행별 원결과를 보존한다.
다른 실행에서 찾은 교훈을 합친 재현율이나 합집합 카드 타당률로 조건을 비교하지 않는다.
초안·최종 통과·보류 같은 카드 단계도 섞지 않으며 대상 단계를 사전 고정한다.

모든 분모 0은 N/A다. 교훈 없는 문서 재현율이나 카드 없는 실행 타당률을 0%·100%로 처리하지 않는다.
문서별·합산 분모와 경계를 공개하고 경계 제외 점수만으로 비교하지 않는다.

## 7. G0 밖 교훈과 공정한 비교

G0 밖이라는 이유만으로 부당이 아니다. 이미 G0에 대응하는 카드의 일부라도 다른 독립 교훈이
있으면 **G+ 후보**에 넣고 원문 위치·인용·독립성·충분성·타당/부당/경계·겹치는 G0 B ID를 기록한다.
그럴듯하다는 이유만으로 추가하지 않는다. 사후 타당 발견 G+는 G0를 덮어쓰지 않는다.

- 최초 결과는 G0 기준으로 보존한다.
- 비교 대상 전체의 발견을 출처를 가려 모으고 중복·분할·범위를 정리한다.
- 공통 확장표 G0∪G+로 모든 조건·실행의 기존 출력을 각각 다시 대응시킨 보조 결과를 제시한다.
- 시스템마다 다른 정답표를 쓰거나 자기 출력에서 찾은 교훈만 자기 점수에 추가하지 않는다.

확장표도 모든 교훈을 망라했다고 보장하지 못한다. 사후 보완 평가라는 한계를 표시한다.

## 8. 버전 관리·사후 오류·재시험

독립 원본·정렬표·불일치 사유·조정 결과·필수 조건·G0/G+·입력·판정 정보·실행 결과에 버전과
SHA-256을 남긴다. G0 확정 날짜·해시가 해당 문서의 최초 생성 시점보다 앞서는지 기록한다.
출력 존재 여부를 확인할 수 없으면 비노출 G0로 주장하지 않는다.

출력을 본 뒤 G0·필수 조건을 덮어쓰지 않는다. 명백한 ID·기록 오류도 원본과 수정 이력을 보존하고
영향을 받는 모든 조건·실행에 동일하게 적용한 보조 재집계를 구분한다.
분할·충분성·범위·완전 기준 변경은 영향 범위를 재판정하고 변경 전 결과를 남긴다.
출력에 맞춘 기준·시스템 변경 또는 G+를 튜닝에 사용했다면 기존 문서 재실행은 개발 결과다.
확증 비교는 새 프로젝트 홀드아웃과 사전에 고정한 기준/G0를 사용한다.

## 9. 가상 판정 예시

**다음은 절차 설명용 가상 예시이며 실제 데이터·관측·정답표가 아니다.**

1. **분리와 공통 근거:** 배치 재실행 중 중복 적재와 실패 구간 식별 어려움이 기록되어 있다.
   적재 멱등성과 배치별 처리 이력이 각각 근거로 지지되면 독립 교훈 두 개다.
   같은 장애 기록을 공통 근거로 쓸 수 있다. 한 카드에 둘을 담으면 포착은 각각 인정하고 합침은 별도다.
2. **통합과 분절:** 체크포인트 저장과 그 지점부터 재시작이 하나의 복구 원칙을 이루면 자동 분리하지
   않는다. G0의 필수 조건이 ‘체크포인트 보존’과 ‘그 위치부터 재시작’이라면 두 카드가 원문에 없는
   연결 없이 함께 충족할 때 분절 완전이다. 각 카드가 단독으로 둘 다 담으면 반복이다.
3. **성공 관측 없음과 근거 부족:** 원문이 API 제한으로 반복 실패했고 재시도 간격 필요성을
   뒷받침한다면 성공 실험 없이도 조건부 교훈을 포함할 수 있다. 관측 없는 처리량 30% 향상 주장은
   부당이다. 별개 오류가 조건부 교훈을 훼손하지 않으면 A 부당과 C 완전이 함께 가능하다.
4. **G0 밖 타당 교훈:** G0에는 배치 멱등성만 있지만 원문에 입력 스키마 사전 검증의 충분한
   근거도 있다면 생성된 검증 교훈은 G+ 후보다. 중복 묶음과 초과 수를 남기고 G0 분모는 유지한다.

## 10. 프로젝트 분할·입력 묶음·실행 전 확인

데이터셋 6개 프로젝트의 분할 단위는 **프로젝트**다. Token Glance는 ADR 0001과 릴리스
v0.1.1 출력이 이미 노출되어 프로젝트 전체를 조율용으로 둔다. 해당 두 문서는 이번 조율에서 제외한다.
나머지 5개 프로젝트(3JMT, Mechadog, Schale Queue, SSAFESTA, Vigilantis)는 모두 홀드아웃으로
사용자 확정했다. 프로젝트 배정표는 준비 보고서와 manifest에 기록한다.
같은 프로젝트의 다른 문서·PDF/DOCX 변환·첨부를 홀드아웃으로 분산시키지 않는다.

프로젝트 배정과 조율 문서 선정·입력 해시는 **G0 작성 전 manifest에 고정했다**.
`split_frozen=true`는 프로젝트 배정을 고정했다는 뜻이다. 홀드아웃의 문서별 선정·제외 목록은
해당 G0 작성 전에 입력 해시와 함께 추가 고정한다. 원본 풀 전체가 평가 대상이라는 뜻은 아니다.
홀드아웃 내용을 개발·조율에 사용하면 그 프로젝트를 재분류하고 새 분할을 사전 고정한다.
‘이전에 출력이 노출되지 않았음’은 이번 세션에서 검증 완료한 사실로 간주하지 않고 사용자 확인을 남긴다.

저장소 밖 입력 묶음은 다음과 같다.

- `g0/`: 원본 `original_markdown`의 바이트 동일 복사본(첨부 포함), 독립 G0 기준 안내,
  요청문 A `judge_request_g0_v1.md`.
- `cards/`: 요청문 B `judge_request_cards_v1.md`만 준비. 실제 카드 내보내기는 G0 확정 후 별도 요청.
- 루트 manifest: 전체 파일 경로·크기·SHA-256. manifest 자체 해시는 저장소 문서 manifest에서 추적한다.

G0 안내는 v0.4와 이 문서 중 G0 작성에 필요한 정의·분할·충분성·필수 조건·경계/생략·유형 표시만
독립적으로 담는다. 검토 기록, `.local`, 출력 관찰 manifest, 실제 생성 출력 사례는 넣지 않는다.
두 작성자에게 **같은 안내·요청문·원문 하나와 필요한 첨부만** 준다. 입력 묶음 전체·다른 판정·
운영자용 분할/노출 기록을 통째로 보내지 않는다. 원본 속 링크는 외부 자료 추가 열람 허가가 아니다.

확정 사항: 표본 25%·최소 10장(부당·경계 전수 포함), 첫 단일 시스템 평가 “1회 실행”,
조건 비교 시에만 조건당 3회, 나머지 5개 프로젝트 홀드아웃, 조율 문서 ADR 0002·perf.md 두 개.
모델 실제 ID·경로, 문서별 출력 비노출 확인과 평가 카드 단계 등 실행 기록은 시작 전에 채운다.
