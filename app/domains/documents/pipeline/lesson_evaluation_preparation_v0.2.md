## 요청문 검토 제안 — 첨부 원문은 수정하지 않음

1. 모든 결과에 필요한 모델 ID·API/웹·날짜·입력 해시가 A의 판정 정보 두 항목과 B의 출력 형식에
   모두 들어 있지는 않다. 이번 문서에서는 운영자가 결과마다 별도 판정 정보 기록을 연결하도록
   했다. 향후 요청문 새 버전에는 공통 판정 정보 구획 추가를 제안한다.
2. B의 규칙 ‘원문과 기준 안내만 근거로 씁니다’는 내용 타당성 A에는 적합하지만 C의 G0 대응에는
   확정 G0도 필요하다. 이번 기준에서 내용 근거는 원문, 대응 기준은 G0 필수 조건으로 명확히 했다.
   향후 B 새 버전에서는 두 역할을 구분하는 문장을 제안한다.

두 요청문은 사용자 제공 내용을 그대로 UTF-8(BOM 없음)·LF·마지막 개행으로 저장했다.
작성 요청문의 표현을 위 제안으로 치환하거나 판정 정보를 본문에 덧붙이지 않았다.

## 추적과 한계

파일 해시는 실제 바이트 SHA-256이다. 기존 manifest가 선언한 LF 정규화 해시는 별도 필드로
보존하고 실제 바이트 해시와 혼동하지 않는다. 외부 manifest는 자신을 제외한 모든 외부 파일을
기록하며, 그 manifest의 해시는 저장소 manifest가 기록한다. 저장소 manifest 자체 해시는 최종 보고에 남긴다.

이 문서와 새 기준·방법론은 출력에 노출된 Codex가 작성했다. 기준의 기원이 완전히 독립적이거나
제3자 검증됐다고 주장하지 않는다. 사용자 조정자는 일반 파이프라인 동작을 알고 있다.
Claude/GPT 실제 모델 ID·경로는 아직 선택하지 않았고, GPT가 단계 모델과 같으면 한계로 남긴다.
새 세션의 저장소·코드·출력·상대 판정 접근 차단과 입력 해시 동일성은 실제 판정 때 기록한다.
