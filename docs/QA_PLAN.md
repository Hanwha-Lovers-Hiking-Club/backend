# QA 계획서

작성일: 2026-10-29

## 목표

발표 데모가 처음부터 끝까지 끊기지 않게 하는 것. 모든 버그보다 **데모를 막는 문제**를 먼저 찾는다.

검증 대상 (MVP 핵심 흐름):
1. **지식 생성:** 문서 업로드 → 진행 표시 → 지식카드 생성
2. **지식 활용:** 챗봇 질문 → 답변 → 근거 카드·원문 확인
3. 지식카드 목록과 상세 화면

### 테스트 문서 목록
- 정상: 서로 관련 있는 프로젝트 2~3개 + 비교용 1개
- 형식별: pdf, docx, md, txt, xlsx
- 경계: 지원 안 하는 형식(pptx, hwp), 50MB 초과, 빈 파일, 한글·특수문자 파일명, 헤딩 없는 txt, 스캔 PDF, 카드로 만들 내용 없는 문서, 여러 문서 동시 업로드

## 기능 연결 확인 방법

1. GitHub의 머지된 PR 목록 확인
   - https://github.com/Hanwha-Lovers-Hiking-Club/backend/pulls?q=is%3Amerged
   - https://github.com/Hanwha-Lovers-Hiking-Club/frontend/pulls?q=is%3Amerged
2. pull 후 최근 커밋 확인: `git pull && git log --oneline -10`
3. 연결 신호 확인 (최상위 폴더에서 실행):

```bash
grep -c "ainvoke" backend/app/domains/documents/service.py              # 1 이상이면 업로드→파이프라인 연결
grep -c "Mock" backend/app/domains/chat/service.py                      # 0이면 챗봇 실제 답변
grep -c "queryMockCards" frontend/src/features/knowledge/api.ts         # 0이면 카드 목록 실제 API
grep -c "SIMULATED" frontend/src/features/document-upload/job-client.ts # 0이면 업로드 진행 실제 서버
```

## 기능별 테스트 케이스

| 기능 | 확인할 것 |
|---|---|
| 업로드 | 형식/용량 오류 메시지, 진행률 표시, 새로고침 후 복구, 실패 시 재시도 |
| 카드 목록 | 검색(제목/요약/키워드), 정렬 3종, 페이지 이동, 빈 결과 |
| 카드 상세 | 근거 문서명·위치·발췌문 표시, 근거 여러 개인 카드 |
| 챗봇 | 스트리밍, 참조 카드 패널, 후속 질문, 오류 메시지 |

## AI 결과 품질 점검 (파이프라인 연결 후)

카드마다 확인:
- [ ] 발췌문이 원문 그대로인가
- [ ] 위치(location)가 맞는가
- [ ] 카드 내용이 근거에 실제로 있는가 (지어낸 내용 없음)
- [ ] 서로 다른 경험이 한 카드에 섞이지 않았는가

챗봇: 질문 10~15개를 정해 두고 답변과 출처가 맞는지 기록.

## 버그 보고

- GitHub Issues에 등록: **재현 절차 / 기대 결과 / 실제 결과 / 스크린샷**
- 심각도: `데모 차단` / `불편` / `사소`
- 데모 차단 버그는 팀 채팅에 바로 공유

## 데모 리허설 (발표 전)

- 발표 시나리오대로 처음부터 끝까지 3회 이상 실행
- 회차마다 소요 시간, 실패 지점 기록
- 백업 준비: 미리 생성해 둔 카드 데이터, 데모 녹화 영상
